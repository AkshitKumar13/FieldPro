TaskForge | Proof of Concept

Task Management Platform

POC detail and high-level architecture for the TaskForge application.

Prepared: 10 September 2026

Technology: .NET MAUI, Shell, CommunityToolkit.Mvvm, dependency injection, and SQLite.

Scope: users, tasks, projects, notifications, documents, dashboard, profile, and device capability demonstrations.

1. POC Overview

TaskForge is a cross-platform task and project management application. The POC demonstrates local data storage, role-aware task views, MVVM screens, Shell navigation, and device capability access.

AreaCurrent implementation
User accessSimple demo-user selection with in-memory session state and logout.
Task managementCreate, assign, view, filter, and update task status.
DashboardShows real task counts from SQLite. Managers and administrators see all tasks; employees see assigned tasks.
DocumentsDisplays the bundled project brief and opens the PDF using the platform launcher.
Device capabilitiesUI for camera capture, GPS lookup, and accelerometer readings with permission feedback.
StorageLocal SQLite database at FileSystem.AppDataDirectory/taskforge.db3.
POC boundary: TaskForge currently has no backend API, cloud synchronization, password authentication, or multi-device data sharing.

4. Task and Document Design

FeatureBehavior
Task countsAdministrators, project managers, and team leads use all task rows. Employees use rows assigned to their user ID.
Task boardShows title, description, due date, visible status, and status picker.
Task creationAuthorized users create tasks through AddTaskCommand, which inserts into SQLite and creates a notification.
Status updatesPicker changes update the TaskItem status in SQLite.
PDF documentThe bundled project-brief.pdf is copied to app storage and opened with Launcher.OpenAsync.
NotificationsAssignment notifications are stored and can be marked read.

5. Device Capability UI

CapabilityScreen behavior
CameraRequests camera permission, captures a photo, saves it in app storage, and displays the result.
GPSRequests location permission and displays latitude and longitude.
AccelerometerStarts and stops monitoring and displays live X, Y, and Z values.
Platform stylingAndroid and iOS Entry handler mapper examples are registered in MauiProgram.

6. Acceptance Criteria

  • Every demo user receives the correct role-aware task counts.
  • Open tasks displays the complete permitted task list.
  • Each task row shows its current status.
  • The project brief PDF opens from the Documents page.
  • Camera, GPS, and accelerometer controls show permission and result states.
  • Logout clears the in-memory session.
  • The Windows target builds successfully.

7. Production Next Steps

  1. Replace demo-user selection with a backend identity service.
  2. Move tasks and documents to an API-backed database.
  3. Add token authentication, server-side authorization, and audit logging.
  4. Persist captured photos and locations against task records.
  5. Add offline synchronization and conflict resolution.
  6. Add automated tests for task counts, task status updates, PDF opening, and device permissions.
